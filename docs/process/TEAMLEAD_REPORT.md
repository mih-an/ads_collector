# Отчёт тимлида — block/click-pages, PR #9

**Задача.** Листание выдачи ЦИАН «как человек» в Chrome: страницы 2+ кликом, паузы прокруткой, заходы на карточки объявлений. PR #9: https://github.com/mih-an/ads_collector/pull/9

**Что сделано.**
- `--page-loader click` (только с `--browser chrome`): страница 1 по ссылке, дальше клик по нумерации или «Дальше»; пауза между запросами — прокрутка страницы рукой человека (`chrome_human.py`).
- `--cards`: 1–2 захода на карточку объявления на клетку в паузах, строка `event=card`; блок на карточке — стоп прогона. `--front` — вкладки на передний план.
- «Источник страниц» переименован в «загрузчик страницы» (`PageLoader`); обход выходит из циклов по итогу страницы `PageOutcome`.
- Без новых флагов поведение прежнее: эталоны ночей совпадают без перегенерации.
- Ревью: 2 круга (круг 1 — 10 частей), блокеров нет, таблицы с пятой колонкой — раздел 8 PR. Тестов 1401, покрытие 100 %, ruff и mypy чистые.

**Кейсы.** Новые 21.91–21.98; дополнены 21.36, 21.78, 21.79, 21.83–21.86, 21.88–21.90.

**Решения уровня 1.** Строки `docs/DECISIONS.md` от 2026-11-16 и 2026-11-17 с меткой block/click-pages (14 до ревью, 5 по кругу 1, 1 по кругу 2 — «BLOCK карточки сильнее ошибки вывода выдачи вперёд»).

**Допущения уровня 2 — ответ Андрея до слияния (раздел 6 PR).**
- 6.1 о данных: объявления ответа на клик — `data.offersSerialized`, `data.offerCount` (на сырье не проверено).
- 6.2 о данных: новое в папке прогона — `kind=click`, `.click.gz`, `sector_end why=no_next_page|same_ids`, `event=card`, `_block_*_0_*`.
- 6.3–6.7: неактивная «Дальше» (`exact=False`, `is_enabled()` без пробы), вкладки при ошибке карточки, модуль `chrome_human.py`, листание одностраничной клетки, 403/429 у Chrome.
- 6.8: числа руки не сверены с пробой `click_test.py` (на сервере её нет) — сверить на Маке.
