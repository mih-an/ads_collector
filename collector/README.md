# collector — боевой сборщик ЦИАН

Пакет, который собирает сырьё ЦИАН по сетке клеток сбора МКАД–ЦКАД
(ТЗ E-42 в репозитории land-monitor). Каждый прогон — каталог
`runs/<метка>/`, один срез для загрузчика (`docs/CIAN_DATA_FORMAT.md`).
Конвейер `land_monitor` (репозиторий land-monitor) этот пакет не
импортирует: он только читает каталоги прогонов.

Номера PR (#116–#122), правила ТЗ E-…, заделы З… и ROADMAP в этом файле
относятся к репозиторию land-monitor.

Код в репозитории — рефакторинг серверного сборщика (PR #121 в репозитории
land-monitor): тот же
обход и тот же формат папки прогона, разложенные по модулям
(`docs/reference/collector_architecture.md`). Это уже не копия
`cian_calib.py`. На сервере по-прежнему работает старый
`~/calib2/cian_calib.py`; выкатка нового пакета — отдельный шаг
(`collector_architecture.md`, 2.7).

| Файл | Что делает |
|---|---|
| `cian_collect.py` | запуск и края: разбирает аргументы в `Settings`, выбирает seed, читает файл клеток и восстанавливает сетку, пауза старта, читает входной билет (`Ticket`); собирает края ночи `Edges` (запрос выдачи через `net.Fetcher`, случайность, часы, сон), запускает `Night`, печатает сетку и итог |
| `net.py` | вся сеть: `Fetcher` — запрос страницы выдачи (банк кук с ротацией из `Set-Cookie`, заголовки браузера, распаковка тела, без редиректов, длительность запроса); сбой сети и битое сжатие ответа 200 — ответ с кодом 0 и деталью |
| `night.py` | ночь: данные (`Settings` с умолчаниями чисел правил ночи, `Ticket`, `Edges`, состояние клеток и ночи), правила обхода функциями без внешнего мира (пул пробы, деление, паузы, «билет сгорел», учёт страницы, дочитанность, ступень, словари `plan.json` и `summary.json`) и дирижёр `Night`: проба, очередь, листание, деление, бюджет, повторы, стоп, Ctrl+C |
| `serp.py` | контракт ЦИАН: ссылка на страницу выдачи, разбор `initialState`, обязательные поля, классы ответа (`OK`, `PAGE_END`, `BLOCK`, `API_CHANGED`, `NET_ERROR`), id объявлений, число страниц; без сети и диска |
| `geometry.py` | геометрия клеток: джиттер, сетка, базовый квадрат, четверти, отсечение, площадь, уплотнение, дети деления; внизу — чтение файла клеток (`load_sectors`) и его атомарная перезапись при делении (`update_tiles_file`) |
| `run_folder.py` | папка прогона: имена, кодировки и порядок записи — `night.log` с эхом в stdout, `plan.json`, страницы `raw/`, `_broken_*`, `_block_*`, снимок охвата, `summary.json` последним |
| `__init__.py` | пустой: делает папку пакетом |
| `status.py` | отдельный скрипт: идёт ли процесс сборщика, итоги трёх последних прогонов; пакет не импортирует. Серверный файл ищет процесс `pgrep -af cian_calib.py`, этот — `cian_collect.py` (поиск меняется при выкатке) |

Числа правил ночи (порог деления, дно, паузы, повторы, пул пробы) —
умолчания `Settings` (`collector/night.py`, решение Андрея 10.11); тайм-аут
сети (`HTTP_TIMEOUT_S`) — в `net.py`; умолчания аргументов запуска
(`RUNS_DIR`, `BUDGET`, `WINDOW_HOURS`) — в `cian_collect.py`; потолок страниц
(`MAX_PAGES`) и размер страницы выдачи (`OFFERS_PER_PAGE`) — в `serp.py`.

Слово `calib` в путях и слово «ступень» (`ladder`) в итоге — наследие
закрытой калибровки ЦИАН-контура, из которой вырос сборщик.

## Запуск

Только как модуль, из папки, где лежит `collector/`:

```
python3 -m collector.cian_collect --geojson <файл клеток> [--budget N] [--window-hours H] [--runs-dir runs] [--smoke-only] [--no-start-delay] [--seed N]
```

`--geojson` обязательный. Запуск файлом (`python3 collector/cian_collect.py`)
не поддерживается: так в `sys.path` попадает сама папка `collector/`, и
`import collector` не найдётся.

## Как устроен обход

- **Ход ночи.** Проба — один запрос страницы 1 случайной мелкой клетки
  (пустая клетка — ещё одна попытка по другой клетке, если в пуле она есть,
  иначе сразу smoke_failed); проба не прошла — обхода нет. Прошла — очередь клеток.
- **Клетки вперемешку, страницы подряд** (с 15.09): листание подряд —
  единственный человеческий паттерн; Referer страницы N — ссылка страницы
  N−1; между клетками пауза длиннее.
- **Весь обход — GET `cat.php`** (страницы 2+ через `p=N`). POST на
  `api.cian.ru` отброшен 11.09: мгновенный 403 при живом билете.
- **Джиттер полигона** — один на пару (клетка, ночь): все страницы клетки
  за ночь идут с одним полигоном, иначе поедет пагинация. Каждую ночь —
  заново от канонической геометрии файла клеток.
- **Деление клетки** [E-42]: totalOffers страницы 1 больше порога — клетку
  не листаем, базовый квадрат режем на 4 четверти, каждая ∩ полигон
  родителя; детей запрашиваем в том же прогоне. Ключи детей: T0706 →
  T0706a/b/c/d (a=ЮЗ, b=ЮВ, c=СЗ, d=СВ), глубже — T0706ab. Родитель
  выбывает навсегда (`collect=false` в файле клеток). На дне деления клетка
  не делится, а листается (решение Андрея 18.09, вариант Б).
- **Снимок охвата** `polygons.geojson.gz` пишется в каждом прогоне (и у
  пробы) перед `summary.json`: каноническая геометрия клеток прогона,
  единственный носитель геометрии для загрузчика.
- **Три класса проблем:** `BLOCK` (403/429, редирект, капча, страница
  проверки Servicepipe) — стоп,
  ступень провалена (порог IP найден); `API_CHANGED` (404/410, контракт
  не тот) — стоп, тело ответа целиком в `raw/_broken_*`, ступень не
  засчитана; `NET_ERROR` (тайм-аут, DNS, 5xx, битое сжатие ответа 200) — до 3 повторов с растущей
  паузой, затем стоп, ступень не засчитана. Ступень засчитана, если ночь
  дошла до конца бюджета или очереди.

## Где лежит на сервере

Основной сервер (`land`), каталог `~/calib2/`:

| Что | Зачем | В git |
|---|---|---|
| `cian_calib.py`, `status.py` | рабочие файлы сервера (старый сборщик одним файлом); в репозитории — пакет после рефакторинга, на сервер ещё не выкачен | нет (`status.py` — копия здесь) |
| `runs/` | каталоги прогонов — сырьё для загрузчика | нет |
| `cian_collect_tiles_v0_3.geojson` | файл клеток сбора; сборщик сам его переписывает при разрезании | нет (копия клеток — `geo/cian_collect_tiles.geojson` в репозитории land-monitor) |
| `cookies.txt`, `ua.txt` | «входной билет»: куки и User-Agent браузера | нет, секрет |
| `tg.conf` | реквизиты Telegram для сторожа `watchdog/` в репозитории land-monitor (права 600); остаётся здесь | нет, секрет |
| `grid_night.out`, `grid_day.out` | вывод cron-запусков | нет |
| `watchdog.log`, `ALERT.txt`, `watchdog.py` | журнал, тревога и копия прежнего сторожа (до переноса cron — рабочие; после — не используются, `watchdog.py` остаётся для отката) | нет |

Секретов в коде нет, они только в файлах:

- сборщик читает `cookies.txt` и `ua.txt` из каталога запуска — поэтому в
  cron стоит `cd /home/andrew/calib2`; запущенный из другого каталога, он
  куки не найдёт и пойдёт анонимно;
- `tg.conf` читает сторож `watchdog/` из клона репозитория land-monitor;
  путь — из `config.toml` того же репозитория, `[watchdog] tg_conf_path`
  (`/home/andrew/calib2/tg.conf`).

Эти имена перечислены в `.gitignore`, чтобы случайно не попасть в коммит,
если файлы окажутся в этой папке.

## Расписание (cron, МСК)

| Время | Что |
|---|---|
| 00:00 | ночной прогон |
| 08:00 | ротация: удаляет сырой HTML прогонов старше 30 дней (E-41; 90 → 30 — решение Андрея 09.11); команда `find` прямо в строке cron с меткой `CIAN-ROTATION`, имени скрипта не содержит |
| 09:30 | сторож `watchdog/` (`--alerts-only`): расписание и перенос — `docs/DEPLOY.md` в репозитории land-monitor, «Сторож» |
| 11:30 | дневной прогон |
| 23:59 | сторож `watchdog/`: сводка и тревоги — `docs/DEPLOY.md` в репозитории land-monitor, «Сторож» |

Прогон начинается не ровно по cron: сначала случайная пауза до 40 минут
(`Settings.start_jitter_max_s`). `--window-hours 7` задаёт средний
интервал между запросами, а не жёсткий стоп: обычно прогон идёт около 7
часов, но может и дольше.

Строки сборщика сейчас (старый файл; при выкатке пакета обе меняются на
`python3 -m collector.cian_collect …` — `collector_architecture.md`, 2.7):

```
0 0 * * * cd /home/andrew/calib2 && python3 cian_calib.py --budget 550 --window-hours 7 --geojson cian_collect_tiles_v0_3.geojson >> grid_night.out 2>&1
30 11 * * * cd /home/andrew/calib2 && python3 cian_calib.py --budget 600 --window-hours 7 --geojson cian_collect_tiles_v0_3.geojson >> grid_day.out 2>&1
```

Остальные строки — `crontab -l` на сервере.

Сейчас (с 10.11) строки сборщика закомментированы пометкой
`#PAUSE-2026-11-10`, копия cron — `~/crontab.2026-11-10.bak` на сервере.
Возврат — снять пометку (решение Андрея 10.11; причина — новая защита ЦИАН,
`docs/STAGE1_HANDOFF.md` в репозитории land-monitor, З155).

## Окна для правок на сервере

Правки — только когда сборщик не работает: **07:00–11:30** и
**18:30–24:00** МСК. Граница условная (см. выше: прогон может затянуться),
решает проверка: `pgrep -af "^python3 cian_"` ничего не выводит. Прежняя
`pgrep -af cian_collect.py` работающий сборщик не видит, а без `^` команда
находит саму себя. После выкатки пакета строка процесса другая
(`python3 -m collector.cian_collect`) — проверка меняется в той же выкатке.

## Как обновить сервер

Автодеплой репозитория land-monitor (`docs/DEPLOY.md` там) обновляет только
`~/projects/land-monitor/`;
в `~/calib2/` он ничего не копирует. Файлы этой папки на сервер сейчас не
копируются (решение Андрея 10.11): выкатка пакета — отдельный шаг после
починки и переезда в свой репозиторий (`collector_architecture.md`, 2.7 и
вопрос 3).

Рабочий сборщик правится только на сервере и только по решению Андрея, в
окне для правок. Путь к будущему — ROADMAP, «сборщик ЦИАН»
(`docs/STAGE1_HANDOFF.md`, Ж10; `docs/DEPLOY.md`, «Боевой сборщик не
автодеплоится» — всё в репозитории land-monitor).

## Правило 6: к ЦИАН — только плановые прогоны

- Вне плановых прогонов — ни одного запроса к ЦИАН.
- Сборщик запускается только cron'ом на сервере.
- Локально — только тесты pytest с подменённой сетью (решение Андрея
  10.11): `tests/test_collector.py`, `tests/test_collector_nights.py`,
  `tests/test_collector_status.py`.

## 45 секторов — заморожено

Прежний контур сбора по 45 секторам работает на VPS 45 секторов
(запасной) со своей копией скриптов в `~/calib/`. Он заморожен: в
репозиторий не входит, из этой папки не обновляется, его файлы не
трогать. Старый сторож стоит и там — без Telegram, только `watchdog.log` и
`ALERT.txt`; на `watchdog/` (репозиторий land-monitor) он не переносится.
