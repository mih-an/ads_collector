# collector — боевой сборщик ЦИАН

Пакет, который собирает сырьё ЦИАН по сетке клеток сбора МКАД–ЦКАД
(ТЗ E-42 в репозитории land-monitor). Каждый прогон — каталог
`runs/<метка>/`, один срез для загрузчика (`docs/CIAN_DATA_FORMAT.md`).
Конвейер `land_monitor` (репозиторий land-monitor) этот пакет не
импортирует: он только читает каталоги прогонов.

Номера PR (#116–#122), правила ТЗ E-…, заделы З… и ROADMAP в этом файле
относятся к репозиторию land-monitor.

Код в репозитории — рефакторинг серверного сборщика (PR #121 в репозитории
land-monitor): тот же
обход и тот же формат папки прогона, разложенные по модулям
(`docs/reference/collector_architecture.md`). Это уже не копия
`cian_calib.py`. На сервере по-прежнему работает старый
`~/calib2/cian_calib.py`; выкатка нового пакета — отдельный шаг
(`collector_architecture.md`, 2.7).

| Файл | Что делает |
|---|---|
| `cian_collect.py` | запуск и края: разбирает аргументы в `Settings` (`read_settings`; в том числе `--transport`, `--browser`, `--page-loader`, `--cookies`, `--ua`, `--chrome-port`, `--chrome-path`, `--chrome-profile`); ранние проверки `check_args` — код 2 до паузы старта (бюджет, `--page-loader click` с браузером без кликов, библиотеки `--transport` и `--browser`, файлы билета у браузера `http`); `build_crawl` выбирает seed, собирает часы `Clock`, случайность и файл клеток `TilesFile`, печатает сетку, делает паузу старта (`pause_before_start`), затем зовёт край `enter_cian` и отдаёт обходу готовый загрузчик страницы; `enter_cian` — две строки: браузер из словаря `BROWSERS` (`BrowserChoice`: библиотека, файлы билета, сборка, `clicks` — умеет ли кликать) по флагу `--browser` и над ним загрузчик страницы из словаря `PAGE_LOADERS` по флагу `--page-loader` (умолчание `PAGE_LOADER` — `url`, создатель `make_url_loader` — `UrlPageLoader` со сном часов обхода; `click` — `make_click_loader`); сборка `HttpBrowser` — `make_http_browser`: входной билет (`read_ticket` → `Ticket`), транспорт (`make_transport`), браузер; сборка `ChromeBrowser` — `make_chrome_browser`: вкладка Chrome (`chrome_browser.connect_chrome_tab`), билет из неё (`read_chrome_ticket`), ожидания вкладки `TabSettings` из констант, рука человека `chrome_human.Human` (сон и часы модуля `time`, случайность обхода), браузер; `main` — четыре строки: настройки, сборка, `collect`, итог |
| `transport.py` | интерфейс сети и общие помощники реализаций: `Transport` (один метод `get`), ответ как с провода `HttpReply`, сбой `NetworkFailure`, тайм-аут `HTTP_TIMEOUT_S`, разбор строки кук, заголовки в нижнем регистре; без сети |
| `urllib_transport.py` | транспорт на urllib (по умолчанию): банк кук с ротацией из `Set-Cookie`, без редиректов, тайм-аут; приносит байты, не распаковывая |
| `httpx_transport.py` | транспорт на внешней библиотеке httpx (`--transport httpx`): то же поведение, что у urllib; httpx импортируется только здесь |
| `browser.py` | интерфейс браузера: `Browser` (билет `ticket`, `fetch(url, referer)` → `FetchedPage`, клик `click_and_catch` → `ClickedPage` или `None`, прокрутка `scroll_page`), входной билет `Ticket`, ответ `FetchedPage`, типы клика (`ClickTarget`, `ResponseWanted`, `ClickedPage`, `BrowserCannotError`); лист пакета, без сети, диска и сжатия; контракт для реализаций — `docs/reference/browser_contract.md` |
| `http_browser.py` | браузер над транспортом `HttpBrowser` — запрос страницы поиска над любым транспортом: заголовки браузера, распаковка тела, длительность запроса; сбой сети и битое сжатие ответа 2xx — ответ с кодом 0 и деталью; кликать и листать не умеет — `BrowserCannotError` |
| `chrome_browser.py` | браузер над вкладкой Chrome `ChromeBrowser` (`--browser chrome`): один `fetch` — один переход вкладки, тело — ответ сервера, у редиректа — первый ответ цепочки, тайм-аут и `net::ERR_*` — ответ с кодом 0; `click_and_catch` — найти ссылку следующей страницы (нет её — «Дальше»), навести мышь и кликнуть рукой человека, поймать ответ (тайм-аут — код 0, `click_timeout`), дождаться загрузки и адреса; `scroll_page` — прокрутка рукой; ожидания вкладки — `TabSettings`; функция-край `connect_chrome_tab` подключается к Chrome по отладочному порту на 127.0.0.1, а если порт молчит — запускает Chrome со своей папкой профиля и ждёт порт; playwright импортируется только внутри неё, поэтому модуль импортируется и без playwright |
| `chrome_human.py` | рука человека `Human` над вкладкой Chrome: движение мыши по дуге с разгоном и торможением, прицел в элемент, клик с задержкой нажатия, прокрутка колесом до низа за заданное время, паузы; перенос пробы `click_test.py`, числа — константы вверху модуля; сон, часы и случайность приходят аргументами |
| `page_loader.py` | загрузчик страницы: интерфейс `PageLoader` (билет `ticket`, `load_page(ключ клетки, кольцо, страница)` → `run_folder.PageAnswer` и пауза на открытой странице `stay_on_page`) и две реализации. «По ссылке» `UrlPageLoader`: ссылка страницы и Referer, запрос через интерфейс `Browser`, разбор ответа (`search_page.classify_page`), пауза — сон. «Кликом» `ClickPageLoader`: страница 1 и повтор после сбоя — по ссылке, следующая — клик `click_and_catch` (ответ API — `search_page.classify_click` и тело для `.click.gz`, документ — как по ссылке; нажимать нечего или те же id — конец клетки), правило `way_to_page`, просьба не по порядку — `PageOrderError`, пауза — прокрутка `scroll_page`; один `load_page` — одно обращение к браузеру, повторы — в обходе; новая реализация — строка словаря `PAGE_LOADERS` в `cian_collect.py` и её создатель; `crawl.py` не трогается |
| `crawl.py` | обход: данные (`Settings` с умолчаниями чисел правил ночи, `Clock`, состояние клеток и ночи), правила обхода функциями без внешнего мира (деление, паузы, «билет сгорел», итог пробы `smoke_entry`, учёт страницы, дочитанность, ступень, словари `plan.json` и `summary.json`, текст итога `summary_text`) и класс `Crawl`: `collect` — открыть прогон, очередь клеток (проба — страница 1 первой клетки), `download_tile` и `download_page` (листание, повторы; страница — одним вызовом загрузчика страницы `load_page`; паузы между страницами и клетками — у загрузчика `stay_on_page`, сон перед повтором — часы), деление на четверти, бюджет, стоп, Ctrl+C; итог — `report` и `print_summary` |
| `search_page.py` | контракт ЦИАН: ссылка на страницу поиска, разбор `initialState`, обязательные поля, классы ответа (`OK`, `PAGE_END`, `BLOCK`, `API_CHANGED`, `NET_ERROR`), id объявлений, число страниц; при листании кликом — что нажать (`PAGE_PARAM`, `NEXT_BUTTON_TEXT`), какой ответ ловить (`is_next_page_response`), разбор ответа на клик (`classify_click`) и признаки конца выдачи (`NO_NEXT_PAGE`, `SAME_IDS`); без сети и диска |
| `geometry.py` | геометрия клеток: джиттер, сетка, базовый квадрат, четверти, отсечение, площадь, уплотнение, дети деления; внизу — файл клеток `TilesFile`: чтение (`tiles`, `grid()`) и атомарная перезапись при делении (`record_split`) |
| `run_folder.py` | папка прогона `RunFolder` (`create`, методы записи) и `say` — единственная печать обхода; имена, кодировки и порядок записи — `night.log` с эхом в stdout, `plan.json`, страницы `raw/` (тело — `.html.gz`, у ответа на клик — `.click.gz`), `_broken_*`, `_block_*`, снимок охвата, `summary.json` последним |
| `__init__.py` | пустой: делает папку пакетом |
| `status.py` | отдельный скрипт: идёт ли процесс сборщика, итоги трёх последних прогонов; пакет не импортирует. Серверный файл ищет процесс `pgrep -af cian_calib.py`, этот — `cian_collect.py` (поиск меняется при выкатке) |

Числа правил ночи (порог деления, дно, паузы, повторы) —
умолчания `Settings` (`collector/crawl.py`, решение Андрея 10.11); тайм-аут
сети (`HTTP_TIMEOUT_S`) и домен кук билета (`COOKIE_DOMAIN`) — в
`transport.py`; умолчания аргументов запуска
(`RUNS_DIR`, `BUDGET`, `WINDOW_HOURS`, `TRANSPORT`, `BROWSER`,
`COOKIES_FILE`, `UA_FILE`, `CHROME_PORT`, `CHROME_PATH`, `CHROME_PROFILE`)
и настройки перехода и ожидания Chrome (`GOTO_TIMEOUT_MS`, `WAIT_UNTIL`,
`PORT_WAIT_S`, `POLL_S`, `CLICK_TIMEOUT_MS`, `LOAD_TIMEOUT_MS`,
`URL_TIMEOUT_MS`) — в `cian_collect.py`; задержки и вероятности руки
человека — в `chrome_human.py`; потолок страниц (`MAX_PAGES`) и размер
страницы выдачи (`OFFERS_PER_PAGE`) — в `search_page.py`.

Слово `calib` в путях и слово «ступень» (`ladder`) в итоге — наследие
закрытой калибровки ЦИАН-контура, из которой вырос сборщик.

## Запуск

Только как модуль, из папки, где лежит `collector/`:

```
python3 -m collector.cian_collect --geojson <файл клеток> [--budget N] [--window-hours H] [--runs-dir runs] [--smoke-only] [--no-start-delay] [--seed N] [--transport urllib|httpx] [--browser http|chrome] [--page-loader url|click] [--cookies <файл кук>] [--ua <файл UA>] [--chrome-port N] [--chrome-path <программа Chrome>] [--chrome-profile <папка профиля>]
```

`--geojson` обязательный. `--budget` — не меньше 1 (иначе выход с кодом 2 до
паузы старта): первый запрос бюджета — проба. Запуск файлом (`python3 collector/cian_collect.py`)
не поддерживается: так в `sys.path` попадает сама папка `collector/`, и
`import collector` не найдётся.

- `--transport` — сетевой транспорт: `urllib` (по умолчанию, стандартная
  библиотека) или `httpx`. httpx — необязательная внешняя библиотека
  (`requirements.txt`, ставится `pip install -r requirements.txt`): без неё
  сборщик с транспортом по умолчанию работает голым `python3`, а
  `--transport httpx` без неё сразу выходит с кодом 2 и подсказкой установки.
- `--browser` — реализация браузера из словаря `cian_collect.BROWSERS`:
  `http` (по умолчанию, `HttpBrowser` над транспортом `--transport`) или
  `chrome` (`ChromeBrowser` над вкладкой Chrome — раздел «Запуск с Chrome
  на Маке»); незнакомое имя — выход argparse с кодом 2. `chrome` требует
  внешнюю библиотеку playwright (`requirements.txt`): без неё — сразу
  выход с кодом 2 и подсказкой установки.
- `--page-loader` — как загружать страницы выдачи (словарь
  `cian_collect.PAGE_LOADERS`): `url` (по умолчанию — каждая страница
  переходом по ссылке, пауза между запросами — сон) или `click` (страница 1
  по ссылке, дальше — клик «следующая страница» во вкладке, пауза — прокрутка
  открытой страницы; раздел «Запуск кликами с Chrome на Маке»). `click`
  только с браузером, который умеет кликать (`--browser chrome`): с
  `--browser http` — выход с кодом 2 до паузы старта.
- `--cookies`, `--ua` — пути к файлам входного билета (только у
  `--browser http`). Без флагов — как раньше: `cookies.txt` и `ua.txt` из
  папки запуска (пустой или отсутствующий `cookies.txt` — без билета).
  Названный флагом, но отсутствующий или пустой файл (0 байт или одни
  пробелы), а также папка вместо файла — выход с кодом 2, в сообщении флаг
  и путь.
- `--chrome-port`, `--chrome-path`, `--chrome-profile` — только у
  `--browser chrome`: отладочный порт Chrome (умолчание 9222), программа
  Chrome (умолчание `/Applications/Google Chrome.app/Contents/MacOS/Google
  Chrome`) и папка профиля, с которой сборщик запускает Chrome (умолчание
  `chrome-profile` в папке запуска; хранится абсолютным путём).

## Запуск с Chrome на Маке

Сборщик ходит на ЦИАН через вкладку настоящего Chrome (`--browser chrome`):
куки, UA и заголовки — самого Chrome. Запускает только Андрей, вручную
(правило 6 ниже). Нужна библиотека playwright из `requirements.txt` (в
`.venv` репозитория она есть); команда `playwright install` не нужна —
сборщик подключается к установленному Chrome.

Файл клеток — копия `geo/cian_collect_tiles.geojson` из репозитория
land-monitor, положенная в `~/cian_chrome/`: обычный прогон (не
`--smoke-only`) переписывает его при делении клеток.

Из корня репозитория:

```
.venv/bin/python -m collector.cian_collect --browser chrome --chrome-profile ~/cian_chrome/profile --geojson ~/cian_chrome/cian_collect_tiles.geojson --runs-dir ~/cian_chrome/runs --smoke-only
```

Без `--smoke-only` — обычный прогон (с паузой старта до 40 минут; убрать —
`--no-start-delay`). Папка профиля — отдельная папка **вне репозитория**,
не основной профиль Chrome: в ней живут куки ЦИАН (секрет).

Что сборщик делает сам:

1. Подключается к Chrome по отладочному порту `--chrome-port` (9222) на
   127.0.0.1, не накладывая на профиль Chrome умолчаний Playwright. Если
   Chrome с этим портом уже открыт (в том числе человеком,
   который в нём работает) — сборщик возьмёт его первую вкладку и будет
   ходить в ней (нет вкладок — откроет новую).
2. Если порт молчит — запускает Chrome командой `<--chrome-path>
   --remote-debugging-port=<порт> --user-data-dir=<--chrome-profile>` и
   ждёт порт до 30 секунд. Chrome запускается отдельно от сборщика и после
   прогона остаётся открытым: в нём можно работать руками (например,
   пройти проверку ЦИАН, если она появилась).
3. Билет берёт из вкладки: UA — `navigator.userAgent`, куки — те, что
   Chrome послал бы на `https://www.cian.ru`; возраста у таких кук нет — в
   итоге «билет: есть» без часов, в `plan.json` и `summary.json`
   `cookie_age_h` — `null`. В первый раз профиль пуст — билета нет;
   откройте в этом Chrome `https://www.cian.ru`, и со следующего запуска
   куки будут.

`--cookies` и `--ua` с `--browser chrome` не используются: файлы билета не
проверяются и не читаются. `--transport` тоже не используется (сеть — у
самого Chrome), но библиотека выбранного `--transport` всё равно
проверяется при запуске (`--transport httpx` без httpx — выход с кодом 2).

Текст ошибки «Chrome не открыл порт …» кончается причиной — первой строкой
последней ошибки подключения Playwright.

Если сборщик вышел с `--browser chrome: Chrome не открыл порт …` или
`--browser chrome: не удалось запустить Chrome …`:

- проверьте `--chrome-path`: по этому пути должна лежать программа Chrome
  (на Маке — `…/Google Chrome.app/Contents/MacOS/Google Chrome`, а не сама
  папка `.app`);
- Chrome с этой папкой профиля уже открыт без отладочного порта — закройте
  это окно Chrome (Cmd+Q) и запустите сборщик снова: второй Chrome с тем же
  профилем порт не откроет;
- порт занят другой программой — укажите другой `--chrome-port`
  (например, 9333);
- `--chrome-profile` — отдельная папка, не основной профиль Chrome
  (`~/Library/Application Support/Google/Chrome`): с основным профилем
  Chrome отладочный порт не открывает.

## Запуск кликами с Chrome на Маке

Тот же Chrome, что в разделе выше, но страницы 2 и дальше сборщик листает
кликом, как человек (`--page-loader click`): страница 1 клетки — переходом
по ссылке, следующая — клик по ссылке с её номером (нет её — по кнопке
«Дальше») во вкладке. Запускает только Андрей, вручную (правило 6 ниже);
подготовка (playwright, копия файла клеток, папка профиля) — как в разделе
выше.

Из корня репозитория:

```
.venv/bin/python -m collector.cian_collect --browser chrome --page-loader click --chrome-profile ~/cian_chrome/profile --geojson ~/cian_chrome/cian_collect_tiles.geojson --runs-dir ~/cian_chrome/runs --no-start-delay
```

`--budget` и `--window-hours` — как у обычного прогона (паузы между
запросами — окно / бюджет); `--smoke-only` здесь смысла не
имеет — проба читает только страницу 1, а она всегда по ссылке. Папка
профиля — отдельная папка вне репозитория, не основной профиль Chrome.

Что меняется по сравнению с `--page-loader url`:

1. Пауза между запросами проходит на открытой странице: вместо сна Chrome
   листает её колесом до низа за то же время (и между клетками тоже).
2. Клик без ответа за 60 с — сбой сети (`click_timeout`): та же страница
   повторяется переходом по ссылке, следующая — снова кликом.
3. Нажимать нечего (нет ни ссылки на следующую страницу, ни активной
   «Дальше») или клик принёс те же объявления, что прошлая страница, —
   конец клетки: в `night.log` — `sector_end why=no_next_page` или
   `why=same_ids`, в итоге stdout — строка «КОНЕЦ КЛИКОМ <клетка>: …».
4. В папке прогона у страницы, пришедшей кликом, — `raw/<клетка>_p<N>.json.gz`
   и полный ответ клика `raw/<клетка>_p<N>.click.gz` (вместо `.html.gz`);
   в строке запроса `night.log` и задаче `plan.json` — `kind=click`
   (`docs/CIAN_DATA_FORMAT.md`).

С `--browser http` загрузчик `click` не запускается: выход с кодом 2 до
паузы старта.

## Проба с Mac своим билетом

Проба (`--smoke-only`) — страница 1 первой клетки очереди: жив ли доступ с
этим билетом; один запрос, при сбое сети — до 3 повторов. Её
запускает только Андрей, вручную (правило 6 ниже — про плановые прогоны).

1. Билет из браузера. В Chrome откройте `https://www.cian.ru`, DevTools
   (`Cmd+Option+I`) → вкладка Network → обновите страницу → выберите
   первый запрос — документ `www.cian.ru` → Headers → Request Headers.
   Нужны два заголовка запроса: `cookie` и `user-agent`.
2. Сохраните их в два файла **вне репозитория** (например,
   `~/cian_ticket/`):
   - `cookies.txt` — значение заголовка `cookie` как есть, одной строкой
     (вида `name1=value1; name2=value2`), без слова `cookie:`;
   - `ua.txt` — значение заголовка `user-agent` одной строкой.
3. Из корня репозитория:

   ```
   .venv/bin/python -m collector.cian_collect --smoke-only --geojson <файл клеток> --cookies ~/cian_ticket/cookies.txt --ua ~/cian_ticket/ua.txt --runs-dir ~/cian_ticket/runs
   ```

   То же на транспорте httpx — добавить `--transport httpx`:

   ```
   .venv/bin/python -m collector.cian_collect --smoke-only --geojson <файл клеток> --cookies ~/cian_ticket/cookies.txt --ua ~/cian_ticket/ua.txt --runs-dir ~/cian_ticket/runs --transport httpx
   ```

   Пауза старта у `--smoke-only` не делается. Итог — в stdout и в папке
   прогона `<runs-dir>/ГГГГ-ММ-ДД_ЧЧММ-smoke/`.

Куки и UA — секрет: в репозиторий их не класть, в чаты и описания PR не
вставлять. Файл клеток (`--geojson`) — копия клеток сбора (например,
`geo/cian_collect_tiles.geojson` из репозитория land-monitor); при пробе он
не переписывается: проба не делит клетки.

## Как устроен обход

- **Ход ночи.** Отдельного запроса пробы нет: проба — страница 1 первой
  клетки очереди, обычный запрос обхода (сбой сети — повторы, как везде).
  Стоп на ней — `smoke_failed`, обхода дальше нет; пустая клетка — проба
  вида `EMPTY`, обход идёт дальше. Итог — ключ `smoke` в `plan.json` и
  `summary.json`.
- **Клетки вперемешку, страницы подряд** (с 15.09): листание подряд —
  единственный человеческий паттерн; Referer страницы N — ссылка страницы
  N−1; между клетками пауза длиннее.
- **Весь обход — GET `cat.php`** (страницы 2+ через `p=N`). POST на
  `api.cian.ru` отброшен 11.09: мгновенный 403 при живом билете.
- **Джиттер полигона** — один на пару (клетка, ночь): все страницы клетки
  за ночь идут с одним полигоном, иначе поедет пагинация. Каждую ночь —
  заново от канонической геометрии файла клеток.
- **Деление клетки** [E-42]: totalOffers страницы 1 больше порога — клетку
  не листаем, базовый квадрат режем на 4 четверти, каждая ∩ полигон
  родителя; детей запрашиваем в том же прогоне. Ключи детей: T0706 →
  T0706a/b/c/d (a=ЮЗ, b=ЮВ, c=СЗ, d=СВ), глубже — T0706ab. Родитель
  выбывает навсегда (`collect=false` в файле клеток). На дне деления клетка
  не делится, а листается (решение Андрея 18.09, вариант Б).
- **Снимок охвата** `polygons.geojson.gz` пишется в каждом прогоне (и у
  пробы) перед `summary.json`: каноническая геометрия клеток прогона,
  единственный носитель геометрии для загрузчика.
- **Три класса проблем:** `BLOCK` (403/429, редирект, капча, страница
  проверки Servicepipe) — стоп,
  ступень провалена (порог IP найден); `API_CHANGED` (404/410, контракт
  не тот) — стоп, тело ответа целиком в `raw/_broken_*`, ступень не
  засчитана; `NET_ERROR` (тайм-аут, DNS, 5xx, битое сжатие ответа 200) — до 3 повторов с растущей
  паузой, затем стоп, ступень не засчитана. Ступень засчитана, если ночь
  дошла до конца бюджета или очереди.

## Где лежит на сервере

Основной сервер (`land`), каталог `~/calib2/`:

| Что | Зачем | В git |
|---|---|---|
| `cian_calib.py`, `status.py` | рабочие файлы сервера (старый сборщик одним файлом); в репозитории — пакет после рефакторинга, на сервер ещё не выкачен | нет (`status.py` — копия здесь) |
| `runs/` | каталоги прогонов — сырьё для загрузчика | нет |
| `cian_collect_tiles_v0_3.geojson` | файл клеток сбора; сборщик сам его переписывает при разрезании | нет (копия клеток — `geo/cian_collect_tiles.geojson` в репозитории land-monitor) |
| `cookies.txt`, `ua.txt` | «входной билет»: куки и User-Agent браузера | нет, секрет |
| `tg.conf` | реквизиты Telegram для сторожа `watchdog/` в репозитории land-monitor (права 600); остаётся здесь | нет, секрет |
| `grid_night.out`, `grid_day.out` | вывод cron-запусков | нет |
| `watchdog.log`, `ALERT.txt`, `watchdog.py` | журнал, тревога и копия прежнего сторожа (до переноса cron — рабочие; после — не используются, `watchdog.py` остаётся для отката) | нет |

Секретов в коде нет, они только в файлах:

- сборщик читает `cookies.txt` и `ua.txt` из каталога запуска — поэтому в
  cron стоит `cd /home/andrew/calib2`; запущенный из другого каталога, он
  куки не найдёт и пойдёт анонимно;
- `tg.conf` читает сторож `watchdog/` из клона репозитория land-monitor;
  путь — из `config.toml` того же репозитория, `[watchdog] tg_conf_path`
  (`/home/andrew/calib2/tg.conf`).

Эти имена перечислены в `.gitignore`, чтобы случайно не попасть в коммит,
если файлы окажутся в этой папке.

## Расписание (cron, МСК)

| Время | Что |
|---|---|
| 00:00 | ночной прогон |
| 08:00 | ротация: удаляет сырой HTML прогонов старше 30 дней (E-41; 90 → 30 — решение Андрея 09.11); команда `find` прямо в строке cron с меткой `CIAN-ROTATION`, имени скрипта не содержит |
| 09:30 | сторож `watchdog/` (`--alerts-only`): расписание и перенос — `docs/DEPLOY.md` в репозитории land-monitor, «Сторож» |
| 11:30 | дневной прогон |
| 23:59 | сторож `watchdog/`: сводка и тревоги — `docs/DEPLOY.md` в репозитории land-monitor, «Сторож» |

Прогон начинается не ровно по cron: сначала случайная пауза до 40 минут
(`Settings.start_jitter_max_s`). `--window-hours 7` задаёт средний
интервал между запросами, а не жёсткий стоп: обычно прогон идёт около 7
часов, но может и дольше.

Строки сборщика сейчас (старый файл; при выкатке пакета обе меняются на
`python3 -m collector.cian_collect …` — `collector_architecture.md`, 2.7):

```
0 0 * * * cd /home/andrew/calib2 && python3 cian_calib.py --budget 550 --window-hours 7 --geojson cian_collect_tiles_v0_3.geojson >> grid_night.out 2>&1
30 11 * * * cd /home/andrew/calib2 && python3 cian_calib.py --budget 600 --window-hours 7 --geojson cian_collect_tiles_v0_3.geojson >> grid_day.out 2>&1
```

Остальные строки — `crontab -l` на сервере.

Сейчас (с 10.11) строки сборщика закомментированы пометкой
`#PAUSE-2026-11-10`, копия cron — `~/crontab.2026-11-10.bak` на сервере.
Возврат — снять пометку (решение Андрея 10.11; причина — новая защита ЦИАН,
`docs/STAGE1_HANDOFF.md` в репозитории land-monitor, З155).

## Окна для правок на сервере

Правки — только когда сборщик не работает: **07:00–11:30** и
**18:30–24:00** МСК. Граница условная (см. выше: прогон может затянуться),
решает проверка: `pgrep -af "^python3 cian_"` ничего не выводит. Прежняя
`pgrep -af cian_collect.py` работающий сборщик не видит, а без `^` команда
находит саму себя. После выкатки пакета строка процесса другая
(`python3 -m collector.cian_collect`) — проверка меняется в той же выкатке.

## Как обновить сервер

Автодеплой репозитория land-monitor (`docs/DEPLOY.md` там) обновляет только
`~/projects/land-monitor/`;
в `~/calib2/` он ничего не копирует. Файлы этой папки на сервер сейчас не
копируются (решение Андрея 10.11): выкатка пакета — отдельный шаг после
починки и переезда в свой репозиторий (`collector_architecture.md`, 2.7 и
вопрос 3).

Рабочий сборщик правится только на сервере и только по решению Андрея, в
окне для правок. Путь к будущему — ROADMAP, «сборщик ЦИАН»
(`docs/STAGE1_HANDOFF.md`, Ж10; `docs/DEPLOY.md`, «Боевой сборщик не
автодеплоится» — всё в репозитории land-monitor).
