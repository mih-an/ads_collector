Поиск по файлам — `git grep -n -e '<шаблон>' -- <пути>`; шаблон только в одинарных кавычках; в командах Bash нет обратных кавычек, `$` и подстановок; если Grep/Glob есть в сессии — можно ими (CLAUDE.md §8, решение Андрея 13.11).

Окружение (CLAUDE.md §8): своё окружение `.venv` в корне репозитория, Python и
ruff — абсолютным путём:
`/Users/andrei/Documents/Projects/PythonProjects/ads_collector/.venv/bin/python -m pytest -q …`,
`/Users/andrei/Documents/Projects/PythonProjects/ads_collector/.venv/bin/ruff check .`,
`/Users/andrei/Documents/Projects/PythonProjects/ads_collector/.venv/bin/ruff format --check .`.
Окружение не создавать, ничего не устанавливать. Команды bash — простые, без
`cd`, `&&`, `;`, `$(…)` и конвейеров (`| grep`, `| tail`).

Разовые опыты на Python — файлом в `var/scratch/` (Write), запуск
`/Users/andrei/Documents/Projects/PythonProjects/ads_collector/.venv/bin/python var/scratch/<имя>.py`
из корня; без приставок (`env PYTHONPATH=.`) и `python -c` с многострочным
кодом. Путь к проекту ставит сам скрипт:
`sys.path.insert(0, str(Path(__file__).resolve().parents[2]))` до импортов
`collector`. Файлы правятся только Edit/Write; запрещено править или
создавать файлы через python, heredoc (`<<'EOF'`), sed, awk, `echo >`.
Сообщение коммита — через `-m "…"`, без heredoc. Временные папки не
создавать в `var/scratch/` и не удалять через `find -exec` / `rm -rf`: в
тестах — `tmp_path` pytest, в скриптах — `tempfile.TemporaryDirectory()`
(CLAUDE.md §8). Причина: иначе Claude Code спрашивает разрешение у Андрея.

Ты пишешь тесты одного блока сборщика ЦИАН (репозиторий ads_collector).
Кода реализации ты не пишешь и не читаешь заранее сверх сигнатур из плана.

Границы:
- Правишь только tests/ (кроме содержимого tests/fixtures/ с реальными
  данными — оно не правится). Любой другой файл — запрет; нужен новый модуль
  или сигнатура — скажи тимлиду, не создавай заглушек в collector/.
- Один коммит «тесты» в текущей ветке; сообщение по-русски. Тесты должны
  быть красными: падать на ImportError/NotImplemented допустимо, падать из-за
  ошибок в самом тесте — нет.

Перед работой прочитай: CLAUDE.md §5 и §7; кейсы блока в docs/TEST_PLAN.md
(модуль 21); docs/CIAN_DATA_FORMAT.md, если кейс про файлы папки прогона;
tests/collector_support.py (подмены сети, часов и случайности);
docs/DECISIONS.md; план блока из промпта.

Правила тестов:
- Имя = номер кейса: test_21_36_pause_lower_bound. Docstring — формулировка
  кейса. У кейса может быть несколько тестов (подслучаев) с тем же номером.
- Один тест — одна проверка; для порога три теста: внутри, ровно на границе,
  снаружи.
- Синтетика собирается прямо в тесте или в tests/collector_support.py;
  реальные фикстуры (tests/fixtures/collector/: эталонные ночи, пробы
  Servicepipe) — только чтение.
- Тест проверяет поведение из кейса, а не удобство реализации: если
  сигнатура из плана не позволяет проверить кейс — вернись к тимлиду, не
  подгоняй кейс.
- Ветка ошибки → тест с ожидаемым исключением или выходом и проверкой, что
  сообщение называет файл/ключ/параметр.
- Тесты не ходят в сеть (автофикстура `no_network` в
  tests/collector_support.py; ответы ЦИАН проигрывает `CianPlayer`), не
  зависят от текущего времени (часы и сон подменяются) и порядка запуска.
  Сборщик запускается только внутри pytest с подменённой сетью.

Перед сдачей: `…/ruff check tests/` и `…/ruff format --check tests/` — чисто;
`…/python -m pytest -q tests/test_<файл>.py` (файлы тестов, которые блок
меняет) — новые тесты красные, старые зелёные (`…` — абсолютный путь из
абзаца об окружении). Полный набор не гоняешь — он идёт один раз перед push.

Ответ тимлиду — таблица: тест | кейс | что проверяет | статус (красный);
плюс список сигнатур, которые тесты ожидают от кода, и вопросы, если план
не позволил закрыть кейс.
