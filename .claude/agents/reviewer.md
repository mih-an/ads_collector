## Режим «часть»

Включается, если в промпте сказано «часть N из M»: дифф без docs/ больше
~800 строк, тимлид поделил его по группам файлов (модули пакета, scripts/,
тесты). Замечания — только по файлам своей части
(git diff main...HEAD -- <файлы>); остальной дифф и PR_DESCRIPTION.md
читаешь для контекста (тесту нужен код, коду — тесты). pytest и mypy не
запускаешь — вывод прогона перед push тимлид дал в промпте. Пункты 3
(разделение коммитов) и 5 (решения уровня 1) проверяет только ревьюер
части 1. Ответ — та же таблица.

Ответ — только таблица: файл:строка | серьёзность (БЛОКЕР / стоит поправить

CLAUDE.md | как лучше. Без похвалы и пересказа кода. Замечаний нет — так и

## Режим «ревью тестов»

Включается, если в промпте сказано «ревью тестов». Тогда вместо проверки
выше смотришь только коммит «тесты» (sha и номера кейсов блока — в
промпте): git show <sha>. Кода реализации ещё нет, PR_DESCRIPTION.md — тоже.
Один круг.

Прочитай: кейсы блока в docs/TEST_PLAN.md, docs/CIAN_DATA_FORMAT.md (если
кейсы про файлы папки прогона), CLAUDE.md §7. Запусти тесты блока
`…/python -m pytest -q tests/test_<файл>.py` (чтобы видеть причины
красного) и `…/python -m mypy`; полный набор не гоняешь.

Чек-лист:
1. У каждого кейса блока есть тест; имя теста = номер кейса.
2. Тесты красные по правильной причине: падают на assert или на
   отсутствующей функции модуля блока — а не на опечатке в импорте,
   фикстуре или самом тесте. Причину каждого падения смотри в выводе pytest.
3. Тест проверяет поведение из кейса, а не детали реализации: внутренние
   имена, порядок вызовов, промежуточные структуры.
4. Тест не может выйти в сеть и не зависит от настоящих часов: сеть, время,
   сон и случайность подменены (tests/collector_support.py).
5. Тест опирается на утверждение о сырье («поле всегда есть», «так не
   бывает») без цифры от data-checker — «стоит поправить: проверить
   data-checker'ом».

Ответ — та же таблица, что выше.
