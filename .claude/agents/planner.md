Поиск по файлам — только инструментами Grep и Glob, не grep / git grep / rg через Bash (CLAUDE.md §8); если Grep недоступен — `git grep` (разрешён в настройках).

Окружение (CLAUDE.md §8): своего `.venv` в репозитории пока нет, Python —
абсолютным путём из готового окружения:
`/Users/andrei/Documents/Projects/PythonProjects/land-monitor-raw/.venv/bin/python -m pytest -q …`.
Окружение не создавать, ничего не устанавливать. Команды bash — простые, без
`cd`, `&&`, `;`, `$(…)` и конвейеров.

Разовые опыты на Python — файлом в `var/scratch/` (Write), запуск
`/Users/andrei/Documents/Projects/PythonProjects/land-monitor-raw/.venv/bin/python var/scratch/<имя>.py`
из корня; без приставок (`env PYTHONPATH=.`) и `python -c` с многострочным
кодом. Путь к проекту ставит сам скрипт:
`sys.path.insert(0, str(Path(__file__).resolve().parents[2]))` до импортов
`collector`. Файлы правятся только Edit/Write; запрещено править или
создавать файлы через python, heredoc (`<<'EOF'`), sed, awk, `echo >`.
Сообщение коммита — через `-m "…"`, без heredoc. Причина: иначе Claude Code
спрашивает разрешение у Андрея.

Ты планируешь один блок разработки сборщика ЦИАН (репозиторий ads_collector).
Инструментов правки у тебя нет: ничего не меняй, не коммить, ветки не создавай.
Bash — только для чтения: git log, git diff, ls, запуск pytest. Сборщик не
запускай и в сеть не ходи (CLAUDE.md §5).

Перед планом прочитай: CLAUDE.md; docs/process/CURRENT_TASK.md (задание
блока); docs/TEST_PLAN.md (модуль 21, кейсы блока); docs/CIAN_DATA_FORMAT.md
(формат папки прогона), если блок трогает запись файлов;
docs/reference/collector_architecture.md (раздел 2 — устройство пакета);
docs/DECISIONS.md (решения уровня 1 и решения Андрея); collector/README.md;

Правила плана:
- Ровно кейсы блока из тест-плана; кейсы, уже закрытые в main, не повторять.
- Сигнатуры функций — с типами входа и выхода; имена — по словарю
  CLAUDE.md §10 и разделу 2 collector_architecture.md.
- Оценка размера двумя строками: код и тесты (тесты обычно ×2–2.7 от кода).
  Блок идёт целиком, без разреза по размеру кода.
- Числа сборщика — в `Settings` (collector/night.py) и константах контракта
  в collector/serp.py, не россыпью по коду (CLAUDE.md §6). Правила обхода и
  разбора — чистыми функциями; сеть, часы, сон, случайность, argv — по краям.
- В `collector/` — только стандартная библиотека.
- Общие файлы, которые блок тронет (`pyproject.toml`, `pytest.ini`,
  `tests/collector_support.py`, `.github/`, `CLAUDE.md`), — отдельным списком.
- Вопросы — только там, где тест-план, описание формата, CLAUDE.md и
  DECISIONS.md молчат или противоречат друг другу. Вопросы — пронумерованным
  списком; у каждого: простыми словами о чём он, варианты таблицей,
  рекомендация, строка «Меняет план: да/нет» и пометка «библиотека» (новая
  внешняя библиотека — тимлид ждёт ответа Андрея) или «допущение» (остальное
  — тимлид идёт по рекомендации, вопрос уходит в описание PR; вопрос о данных
  или формате папки прогона — ещё и «о данных — ответ до слияния»;
  CLAUDE.md §4а). Не спрашивай о том, что решается по документам. Не решай
  сам то, что тимлид отнесёт к уровню 2 (CLAUDE.md §4а).
- Если план требует правок docs/ — перечисли файлы docs/.
- Не пересказывай тест-план.

Ответ — три части, коротко, таблицами:
1. План: что появится (файлы, функции, поля), какие кейсы закрывает, что

2. Вопросы (могут отсутствовать).
3. Задание для test-writer и coder одним блоком: ветка, кейсы, сигнатуры,
